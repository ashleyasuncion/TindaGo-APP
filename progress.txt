PROJECT OVERVIEW
--------------------------------------------------------------------------------
A native Android sari-sari store management app built with Kotlin and Jetpack
Compose. Ported from the HTML/CSS/JS prototype (TindaGo web app).

Originally built as "Sari-Sari Smart" (July–Aug 2026). Rebranded to "TindaGo"
on Aug 18, 2026.

All 5 frontend stages + Room Database + Notifications + Testing:
  Stage 1 — Project Foundation ✓
  Stage 2 — 16 Screens with full UI ✓
  Stage 3 — Tutorial System (12 page-specific tutorials) ✓
  Stage 4 — Room Database (9 entities, 9 DAOs, AppDatabase, AppRepository) ✓
  Stage 5 — UX Polish (snackbar, confirmations, nav badges) ✓
  Stage 6 — Local Notifications (WorkManager, 4 channels, rules + throttle) ✓
  Tests  — 89 unit tests (all passing) ✓

Three pillars: Stock Tracker | Daily Cash Summary | Utang Notebook | SMS Notifications

APP ARCHITECTURE (Current)
================================================================================

Tech Stack:
  - Language: Kotlin 2.0.21
  - UI: Jetpack Compose + Material3
  - Navigation: Navigation Compose
  -  Persistence: Room Database (11 entities, 11 DAOs, AppDatabase, AppRepository)

V2.0h — TUTORIAL AUTO-SCROLL RESTORATION (MOBILE) — DONE
Date: Aug 20, 2026
Status: IMPLEMENTED + VERIFIED

PROBLEM:
- Tutorial auto-scroll-to-highlight was broken in the mobile app
- The code existed in TutorialOverlay.kt but could never execute
- Root cause: TutorialOverlay is composed OUTSIDE the scope where screens
  provide LocalScreenScrollState / LocalScreenLazyListState
- The overlay always read null for both scroll states
- 3 screens (StocksScreen, RecordPaymentScreen, NewDebtScreen) also lacked
  scroll state providers entirely

SOLUTION:
- Created TutorialScrollStateHolder (shared mutable state holder) that bridges
  scroll state between screen composables and the TutorialOverlay
- Screens update the holder via LaunchedEffect when they compose
- TutorialOverlay reads from the holder instead of CompositionLocals
- Holder provided at NavGraph level via CompositionLocalProvider
- Added missing scroll state providers to 3 screens

BUILD FIX #1 — Smart cast impossible on delegated properties:
- Using `by rememberUpdatedState(...)` creates Kotlin delegated properties
- Kotlin cannot smart-cast delegated properties (compiler can't prove
  value hasn't changed between null-check and usage)
- Fix: read scrollHolder.scrollState / scrollHolder.lazyListState into
  local vals inside the LaunchedEffect block before null-checking

BUILD FIX #2 — JVM signature clash on TutorialScrollStateHolder:
- `var scrollState by mutableStateOf(...)` auto-generates setScrollState()
  on JVM, which clashed with the explicit `fun setScrollState()`
- Same for lazyListState / setLazyListState
- Fix: changed to backing fields (_scrollState, _lazyListState) with public
  val getters; renamed setters to updateScrollState() / updateLazyListState()
- Updated all 16 screen files that call the renamed methods

COVERAGE — tutorials with steps requiring auto-scroll:

V2.0k — CLOSING REMINDER HOUR DEVICE-AWARE TIME FORMAT (MOBILE) — DONE
Date: Aug 20, 2026
Status: IMPLEMENTED + VERIFIED

PROBLEM:
- Closing Reminder Hour setting displayed time in fixed 24-hour format
  (e.g. "18:00") regardless of the user's device time format preference.
- Changing the device from 24-hour to 12-hour format had no effect on the
  app's time display.
- The raw integer field with ":00" suffix was never designed for locale-aware
  formatting.

SOLUTION:
- Added android.text.format.DateFormat.is24HourFormat(context) detection
  to adapt the display/input to the device's preferred time format.

  24-hour mode: [ 18 ] :00  (unchanged behavior)
  12-hour mode: [ 6 ] :00 [PM]  (12-hour value + AM/PM toggle button)

- The stored closingReminderHour Int (6-21) and DailyCheckWorker

  Room SpecificSale(date, description, quantity) + Product(quantity)

       Match: description == product.name (ignoreCase, SaleBottomSheet convention)
       Output: history[7], dates[7], totalSold, activeDays
    -> Model: SMA=sum/7, EMA alpha=0.5, Trend=linearRegressionNextDay()
       Primary = SMA (most defensible); EMA/Trend shown for comparison
    -> Predict: predictedDaysUntilOut=ceil(stock/avgDaily), suggestedRestock=ceil(avg*7-stock)
    -> Evaluate: ForecastConfidence INSUFFICIENT(0) / LOW(1) / MEDIUM(2-3) / HIGH(4+)
    -> UI: ForecastBadge, ForecastDetailCard, urgentRestocks() lists

Outputs: ForecastResult { avgDaily, emaDaily, trendDaily, predictedDaysUntilOut?,
         suggestedRestockQty, confidence, dailyHistory[7] }
Complexity: O(window + |sales|) per product.
  1 (history,dates)=buildDailyHistory(product,allSales,todayStr,7)
  2 totalSold=sum(history); activeDays=count(history[i]>0)
  3 sma=sum(history)/7; ema=EMA(history,0.5); trend=linRegNextDay(history)
  4 avgDaily=sma
  5 if avgDaily<0.15            predictedDays=null
  6 else if quantity<=0         predictedDays=0
  7 else                        predictedDays=ceil(quantity/avgDaily)
  8 suggested=if avgDaily<0.15 0 else max(0,ceil(avgDaily*7-quantity))
  9 confidence=totalSold==0?INSUFFICIENT : activeDays<=1?LOW : activeDays<=3?MEDIUM : HIGH
 10 return ForecastResult(..., forecastMethod="Statistical ML (7-day Moving Average)")
